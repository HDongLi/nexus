# 模块卡：事件日志（event-log）

| 项         | 内容                                                     |
| ---------- | -------------------------------------------------------- |
| 名字       | `@nexus/event-log`                                       |
| 一句话     | 全平台事件的唯一落点，也是事务性发件箱的表               |
| 2026-11-26 | 随骨架建立。消费、投递、归档都还没有，见下面「不做什么」 |

## 职责

别的模块有了值得别人知道的事，往这里写一条事件。只追加，不更新，不删除。

## 公开接口

- `createEventLog({ db, repo? })` → `EventLog`
  - `emit(input, tx?)`：写一条。给了 `tx` 就和调用方的业务写入在同一个事务里，一起成或者一起败。
  - `list({ type?, subject?, after?, limit? })`：新的在前，最多 200 条。
- 事件信封的形状在 `@nexus/contracts`（`eventEnvelope`），发出之前先过它。

## 事件

本模块自己不发事件。

## 拥有的表

- `events`：事件日志。

## 不做什么

- **不投递**：现在没有消费者，也没有往任务队列转发的中继。第一个真正要订阅事件的模块出现时再定投递语义（至少一次、幂等、顺序），另起决策记录。
- **不归档**：事件表只会长。保留策略等数据量说话。
- **不出 HTTP 路由**：还没有人需要直接读事件流；需要时再加，走 `route()` 声明访问级别。
