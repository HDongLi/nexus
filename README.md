## 跑起来

前提：Node 24.12 以上，pnpm 12。

```sh
pnpm install
pnpm dev
```

终端会打出两个地址：后端的健康探测和页面。端口从 4260 起自动找空闲的，不假设它们空着。Ctrl+C，两个进程一起停。

开发库是进程内的 Postgres（PGlite），第一次启动自动建表，数据落在 `apps/api/.data/`，不需要先装数据库。设了 `DATABASE_URL` 就连真库。

## 第一次用

库里一个人都没有的时候谁也登录不了。先建第一个管理员，再起服务：

```sh
cd apps/api
printf '%s\n' '<口令>' | node src/scripts/create-user.ts --username <用户名> --admin --password-stdin
```

Windows 的 PowerShell 里，把第二行换成 `'<口令>' | node src/scripts/create-user.ts --username <用户名> --admin --password-stdin`。

- 口令只从标准输入读第一行。不走命令行参数，是因为参数会留在 shell 的历史里；脚本也不写日志。
- 口令里有中文等非 ASCII 字符时要当心：Windows 自带的 PowerShell 5.1 往管道里送的是问号（2026-11-27 实测），账号会带着一个错的口令建成，登录时才发现。这种口令改用 PowerShell 7、Git Bash，或者 cmd 的 `echo <口令> | node …`。
- `--admin` 可选，不带建的是普通账号。用户名只能用字母、数字、下划线、连字符，不分大小写地查重。
- 开发库一次只能被一个进程打开，所以**服务在跑的时候先停掉再建号**。不停的话脚本会拒绝，并说明原因。
- 建成时标准输出一行 `created <用户名>`。没建成时退出码不是 0，原因在标准错误，库里不会多出半行。
- 服务放在反向代理后面时，设 `PUBLIC_ORIGIN`（形如 `https://nexus.example.com`，不带路径）。写请求的 `Origin` 要和它对得上；不设就按请求自己的地址比，本机开发不用设。
- 口令最短长度是 `PASSWORD_MIN_LENGTH`，默认 8 个字符，建号和改密都查它。

## 检查

```sh
pnpm verify      # 提交前跑：格式、lint、依赖方向、类型、单元测试、集成测试、契约一致性、迁移可重放
pnpm gate:l3     # 发布前跑：在真浏览器里走一遍
```

| 级别 | 管什么 | 预算 | 冷缓存实测（2026-11-26） |
|---|---|---|---|
| L0 | 格式、lint、依赖方向、编译器版本、请求路径零同步、任务范围 | 10 秒内 | 2 秒 |
| L1 | 类型检查、单元测试 | 30 秒内 | 7.6 秒（装完依赖后的第一次约 15 秒） |
| L2 | 集成测试、契约一致性、迁移可重放 | 5 分钟内 | 10 到 18 秒；2026-11-27 身份模块接入后约 45 秒，多出来的几乎全是建账号脚本的集成测试在起真进程 |
| L3 | 端到端 | 按需 | 14.5 秒 |
