## 它管什么

管账号由管理员来管的部分，和用户组：人员清单、建号、改显示名和管理员位、重置口令、停用与启用、删号；同事名录；用户组的建、改名、换成员、换可见的工程、删。外加把用户组接进工程模块的「谁看得见哪个工程」：这份关系（哪个组看得见哪些工程）归工程模块的一张关系表，身份模块只管组和成员（G-31）。

不管：登录、会话、本人改密（[身份规格](identity.md)，下文的 I 编号）；工程本身（[工程规格](projects.md)，下文的 P 编号），这一片只给 P-10 的判断点接上用户组；单点登录并号、跨实例同步身份、超管、按工程的角色（见「明确不做的」）。

## 术语

| 词 | 意思 |
|---|---|
| 账号 | 身份模块的一行记录：编号、用户名、显示名、口令散列、管理员位、停用时间、创建时间、最近改密时间 |
| 操作者 | 当前登录的账号。这一片的写路由只有管理员走得到，所以操作者都是管理员 |
| 用户组 | 一行记录：编号、名字、成员。不带角色 |
| 成员 | 用户组里的账号编号的集合。一个账号可以在多个组里，也可以不在任何组里 |
| 可见的工程 | 一个用户组看得见的工程编号的集合，成员看得见这些工程。它是工程模块关系表里的行，不记在用户组那一行里 |
| 护栏 | 不许系统失去全部管理员的几条规矩，和「不许动自己」 |
| 码点 | Unicode 码点。长度都按它数，一个四字节字符算一个 |

### 路由与总则

| 路由 | 访问级别 | 请求体 | 成功时 |
|---|---|---|---|
| `GET /api/v1/users` | admin | 无 | 200 `{ "accounts": Account[] }`，按用户名升序 |
| `POST /api/v1/users` | admin | `{ "username", "password", "displayName", "isAdmin" }` | 201 `{ "account": Account }` |
| `GET /api/v1/users/{userId}` | admin | 无 | 200 `{ "account": Account }` |
| `PATCH /api/v1/users/{userId}` | admin | `{ "displayName"?, "isAdmin"? }`，至少带一个 | 200 `{ "account": Account }` |
| `POST /api/v1/users/{userId}/password` | admin | `{ "newPassword": 1 到 128 个字符 }` | 200 `{ "ok": true }` |
| `POST /api/v1/users/{userId}/disable` | admin | 无 | 200 `{ "account": Account }` |
| `POST /api/v1/users/{userId}/enable` | admin | 无 | 200 `{ "account": Account }` |
| `DELETE /api/v1/users/{userId}` | admin | 无 | 200 `{ "ok": true }` |
| `GET /api/v1/people` | user | 无 | 200 `{ "people": User[] }`，按用户名升序 |
| `GET /api/v1/groups` | admin | 无 | 200 `{ "groups": Group[] }`，创建早的在前 |
| `POST /api/v1/groups` | admin | `{ "name", "memberIds"? }` | 201 `{ "group": Group }` |
| `GET /api/v1/groups/{groupId}` | admin | 无 | 200 `{ "group": Group }` |
| `PATCH /api/v1/groups/{groupId}` | admin | `{ "name" }` | 200 `{ "group": Group }` |
| `PUT /api/v1/groups/{groupId}/members` | admin | `{ "userIds": 字符串数组 }` | 200 `{ "group": Group }` |
| `GET /api/v1/groups/{groupId}/projects` | admin | 无 | 200 `{ "projectIds": 字符串数组 }` |
| `PUT /api/v1/groups/{groupId}/projects` | admin | `{ "projectIds": 字符串数组 }` | 200 `{ "projectIds": 字符串数组 }` |
| `DELETE /api/v1/groups/{groupId}` | admin | 无 | 200 `{ "ok": true }` |

`Account` 一律是 `{ "id", "username", "displayName", "isAdmin", "isDisabled", "createdAt", "passwordChangedAt" }` 七个键。`Group` 一律是 `{ "id", "name", "memberIds", "createdAt", "updatedAt" }` 五个键；一个组看得见的工程另问 `GET /api/v1/groups/{groupId}/projects`，回 `{ "projectIds" }`，这两条路由归工程模块（G-31）。`User` 是身份规格定义的四个键。编号都是 UUID；名字都是字符串；两个「是否」是布尔；时间是带时区的 ISO 8601；两个「集合」是编号的数组，没有重复，顺序不表示什么。

路径里的 `userId`、`groupId` 都是编号，不是用户名、组名。用户名和组名是给人看的，以后可能允许改。

| 错误码 | 状态码 | 什么时候 |
|---|---|---|
| `identity_username_taken` | 409 | 建号时用户名已被占用，含只差大小写 |
| `identity_group_name_taken` | 409 | 建组或改名时组名已被占用 |
| `identity_last_admin` | 409 | 这次改动会让系统没有启用的管理员 |
| `identity_self_change` | 409 | 管理员想降级、停用、删除自己，或给自己重置口令 |
| `identity_user_has_projects` | 409 | 要删的账号建过工程。是库的引用约束拒绝的，系统只把它翻译成这个码（G-21） |

找不到一律是已有的 `not_found`（404）；形状不合是已有的 `invalid_request`（400）；没登录是 `auth_required`（401）；登录了但不是管理员是 `auth_forbidden`（403）；口令太短是 `auth_password_too_weak`（400）。`message` 是给人看的，文案不固定。

### 护栏

护栏在写库之前查。三条「最后一个管理员」的规矩查的是同一个数：管理员位为真、且停用时间为空的账号数。

| 编号 | 要求 | 来源 | 验收 |
|---|---|---|---|
| G-18 留一个管理员 | 当管理员的改动会让启用的管理员数变成 0 时（降级、停用、删除最后一个），系统应回 409 `identity_last_admin`，不写库、不发事件。 | 编排者的约定；R137 只数账号总数，停用的也算（identity/registry.py:418-419） | 集成测试——只剩一个启用的管理员时：降级、停用、删除各回 409。有两个启用的管理员时：三个动作对其中任一个都得 200。再造一种：先停用备用的那个（得 200，还剩一个），然后对剩下的那个降级，回 409 |

### 工程可见性

这一组把 P-10 的判断点接上用户组，兑现 P-12。数据分三家：组和成员归身份模块；「哪个组看得见哪些工程」的关系归工程模块；判断和自动挂组都是工程模块的用例。

**裁决（2026-11-27）：关系跟着用它的模块走。** P-12 的验收要的是「建完工程，别人调清单时挂组已经生效」，这是一次写入里的同步可见；事件是事后的，事件日志现在也没有投递。反过来让身份模块进工程模块的事务，又和 `AGENTS.md` 铁律 7 相冲。把关系放进工程模块，建工程的那一个事务写完工程记录、关系、事件，两个问题一起没了；身份模块从此对工程一无所知。

| 编号 | 要求 | 来源 | 验收 |
|---|---|---|---|
| G-31 只依赖一个方向 | 工程模块和身份模块之间应只有「工程模块 → 身份模块」一个方向。工程模块的两张表用引用约束指向身份模块的表，引用的是身份模块公开导出的表定义：工程表的创建者编号指向账号表，不许删（G-21）；关系表的组编号指向用户组表，随组删（G-30）。运行时工程模块只调身份模块一个公开查询「用户组在不在」，别的不调。身份模块不 import 工程模块的任何文件，不读工程的表；工程模块不读身份模块的表。引用约束不算读写：它只让库替两个模块把关，数据还是各写各的。 | 任务书 §3.3 的 P3（模块依赖必须无环；不准读写对方的表）；`AGENTS.md` 铁律 3、7 | `pnpm run arch` 通过。集成测试——把「组在不在」的查询换成恒假的桩：读和整体替换一个组的可见工程都得 404；换成恒真的桩得 200 |

### 事件

由管理员触发的写事件都带 `actorId`（操作者的账号编号）。用户的 `subject` 是用户名，用户组的 `subject` 是组编号。`source` 除了 `projects.visibility.changed` 是 `projects`，都是 `identity`。

| 事件 | 什么时候发 | `subject` | payload 的键 |
|---|---|---|---|
| `identity.user.created` | 建号成功（命令行，或管理员） | 用户名 | `userId`、`isAdmin`、`via`（`cli` 或 `admin`）。`via` 是 `admin` 时另有 `actorId` |
| `identity.user.updated` | 显示名或管理员位变了 | 用户名 | `userId`、`actorId`、`changes` |
| `identity.user.password.reset` | 管理员重置口令 | 用户名 | `userId`、`actorId`、`revokedSessions`（被吊销的会话数） |
| `identity.user.disabled` | 停用 | 用户名 | `userId`、`actorId` |
| `identity.user.enabled` | 启用 | 用户名 | `userId`、`actorId` |
| `identity.user.deleted` | 删号 | 用户名 | `userId`、`actorId`、`groupIds`（删前它在哪些组里） |
| `identity.group.created` | 建组 | 组编号 | `groupId`、`actorId`、`name` |
| `identity.group.renamed` | 组名变了 | 组编号 | `groupId`、`actorId`、`changes` |
| `identity.group.members.changed` | 成员变了 | 组编号 | `groupId`、`actorId`、`changes` |
| `projects.visibility.changed` | 一个组看得见的工程变了：管理员整体替换，或建工程自动挂上。这条由工程模块发，关系表是它的（G-31） | 组编号 | `groupId`、`actorId`、`changes`、`cause`（`admin` 或 `project_created`） |
| `identity.group.deleted` | 删组 | 组编号 | `groupId`、`actorId`、`name`、`memberCount`。它当初看得见哪些工程不记在这里：身份模块不知道，那是工程模块的关系表（事后要查，回放 `projects.visibility.changed`） |

`changes` 只列真变了的键，每个键带 `from` 和 `to`，同工程规格。成员和可见工程的 `from`、`to` 是编号的数组，按原样全量记，不记差集。`identity.user.created` 是第 1 片已有的事件，这一片把 `via` 从只有 `cli` 放宽成两个值，并加了 `actorId`（[身份规格](identity.md) I-39 的事件表写明「这一片只有 `cli`」，是给这里留的）。

## 旧系统的做法与教训

读的是旧仓 `server/nexus_server/` 下的 `identity/registry.py`（全文）、`dev/routers/platform_routes.py`（第 94 到 272 行）、`core/auth.py`（第 145 到 260 行）、`dev/deps.py`、`dev/routers/projects.py`（第 240 到 256 行），页面 `server/web/dev.html`、`prod.html` 的调用处，加 `server/tests/` 里的 `test_dev_groups.py`、`test_dev_identity.py`、`test_identity_groups.py`、`test_identity_separation.py`、`test_boundaries.py`、`test_placeholder_user.py`、`test_identity_write.py`。行号是 2026-11-27 的现状。旧系统一次都没跑过，标「读码所见」的都没有实测。

**旧系统有三种「组」，各管一件事。**

| 旧东西 | 住处 | 管什么 | 写的路由 | 去向 |
|---|---|---|---|---|
| 开发授权组 `dev_groups` | 开发面的配置文件 | 成员、可见的工程、可见的服务器 | R074 | 成员和可见的工程进这一片；可见的服务器归第 6 片 |
| 用户组 `groups` | 生产面的配置文件 | 成员、各工程的角色（使用者或管理员） | R140、R142 到 R144 | 按工程的角色不上开发面，不做 |
| 人员组 `staff_groups` | 开发面的配置文件 | 纯分类标签，单选（一人一栏） | R077 | 已退役；它同时被当成超管的成员名册 |

新版的用户组只有开发授权组的两个维度。「组」这个词在旧系统里指过三种东西，规格里说的「用户组」只是一种。

- **同一个写端点，开发面的闸比生产面严。** `registry.py` 的十二条路由两个面都挂载，写路由都只依赖 `_auth_prod_admin`。这个函数在配置里有某个键的机器上只认管理员旗或超管；在没有的机器上，带开发者旗的会话直接放行（identity/registry.py:248-253）。注释说「写另有追加闸」，那道追加闸叫 `_dev_identity_gate`，只加在开发面的挂载上（dev/app.py:69；dev/deps.py:48-59），生产面的挂载没有（prod/app.py:106）。读码所见：生产面上这些写路由的闸比开发面松。新版只有一种管理员位、一个闸（G-01）。
- **管理操作级别不够回的是 401。** `_auth_prod_admin` 的出口是「401 管理操作需要管理身份」（identity/registry.py:254），已登录但不是管理员也是 401。I-44 已经定了 403。
- **人员清单回什么。** R133 用 `_pub` 剥掉盐和散列两个字段，其余照发，另加一个凭据在场位和一个超管生效位（identity/registry.py:100-105、257-272）。行上有的都在响应里，包括口令版本号，有单点登录身份名和员工编号的也带上。开发面的 R073 更直接，`users` 整表原样回（platform_routes.py:113、123），带盐和散列（B-002）。页面上的人员行用了十来个这样的字段来画徽标（dev.html:3169-3190）。（→ G-05、G-06）
- **建号。** R135 不带口令就建占位号：盐和散列是空串，等单点登录首登来认领；口令下限 6；用户名正则不含点，报错文案却说「还有点和百分号」（identity/registry.py:328-343）。建号能直接带角色、开发者旗、归属工程。开发面上的建号入口已经删掉，建号只在生产面（dev.html:3295-3296 的注释）。（→ G-08 到 G-11）
- **改号什么都能改。** R136 一个请求体能改口令、角色、开发者旗、停用、归属工程、管理员旗、分栏、单点登录身份名、员工编号，每项给了就改，没有任何护栏：能停用自己、删自己、把最后一个管理员降级（identity/registry.py:357-410）。改密的实现是散列换新加口令版本加一，旧票因签名对不上而失效。（→ G-13 到 G-20）
- **删号的两道闸。** 「至少保留一个账号」数的是全部行，停用的、占位的都算（identity/registry.py:418-419）。另一道是「不能是某个工程最后一名在册管理员」，这是生产面的应用角色（identity/registry.py:420-434；`test_delete_last_admin_holder_blocked`）。新版把「至少一个」从账号收紧到启用的管理员；工程管理员那道不上开发面。**删号只从生产面的用户组里摘人，开发授权组里原样留着**：`registry.py` 全文不读不写开发授权组，级联只动一种组（identity/registry.py:108-113、438-446；`test_user_delete_cascades_out_of_groups` 钉的也只是这一种）。被删的人于是留在开发授权组里成了幽灵成员，R073 的幽灵清单就是给这种残留画的警示（platform_routes.py:115-117）。删号的留痕只记用户名，不记它曾在哪些组（identity/registry.py:447）。删号路由复用建号的请求模型，所以请求体里可以夹带口令和角色（identity/registry.py:414）。（→ G-02、G-18、G-21 到 G-23、G-39）
- **谁能看到哪些工程。** 管理员全量；其余是所属各开发授权组的可见工程的并集，每个请求读一次盘现算（core/auth.py:160-172）。来自回环地址的请求一律当管理员（auth.py:176-178）。看得见但不是自己的工程回 403，文案说明它不在你的归属里（dev/deps.py:27-37）。个人直授已经退役，只经组（auth.py:160-163 的注释；`test_dev_scope_reads_local_dev_groups`）。（→ G-32、G-33）
- **挂组那段从未生效。** 建工程后想把工程挂进创建者所属各组，但引用了一个全文件没定义的名字，异常被下一行吞掉（projects.py:245-256）。管理员自己是全量可见，所以没人发现；组员要等管理员在授权面手动拖（B-001）。（→ G-34）
- **授权画布的数据源。** R073 回人员表、开发授权组、人员组、两个「幽灵清单」——组里指向已不存在的账号的成员、指向已注销的服务器的名字（platform_routes.py:102-125）。幽灵清单是文件存储加改名不级联才有的东西。授权画布的写是「读快照、改一个、整份发回」：拖一个人进组，页面把整份成员数组重发（dev.html:3574-3576）。两个管理员同时改同一个组，后发的覆盖先发的。（→ G-28；见「未确定」）
- **开发授权组的写口。** R074 是一个端点一个 `op` 字段分建、改、删。这个端点里没有任何审计调用：建、删、改名、换成员、换工程都不记（platform_routes.py:133-190）。成员必须是开发者（有开发者旗）；可见的工程只滤掉非字符串，**不查这个工程在不在**（platform_routes.py:173-180）；可见的服务器倒是要在登记表里（platform_routes.py:181-187）。重名检查整串相等，40 个字符封顶。（→ G-25、G-27）
- **用户组的写口和审计。** R142 建组记一条管理留痕（identity/registry.py:582），R144 删组记一条（registry.py:614），R143 改组**不记**（registry.py:586-604）。改组时值不是「使用者」或「管理员」的角色被静默丢掉，不是字符串的成员被静默丢掉（registry.py:595-601）。删组不看组里有没有人（B-011）。组的成员还可以是「`identity:` 加某个身份名」，授权时按账号行上的单点登录身份实时展开（registry.py:117-132；`test_identity_groups.py`）——这是对接身份中心的适配。（→ G-36、G-38）
- **超管怎么判。** 账号行上的旗，或者在一个固定名字的人员组里（core/auth.py:227-254）。那个组的唯一写口 R077 没有界面调用、没有审计调用，注释却说留了审计（B-003）。代码注释自己记着，这个判据分叉过：认领闸和人员页各用一套（core/auth.py:227-231）。（→ 不做，见下）
- **页面把判断重做了一遍。** 人员页按「本命服务器」分栏，另有一套超管判定（dev.html:3156-3161）；工程页在服务端过滤之后自己又滤一遍（dev.html:1752）。（→ 这一片页面只显示接口回的东西）

## 明确不做的

- 单点登录并号（R141）：归单点登录那条线。
- 跨实例同步身份（R078、R134、R138、R139）：任务书 §7.1 的身份同步契约，归定制包或契约测试。
- 占位号（R135 的不带口令建号）、认领：为单点登录并存而设。
- 超管（R077、R133 带回的超管位）：这一片的管理员位只有一级。
- 开发者旗（R136 的 `is_dev`）：新版任何启用且有口令的账号都能登录、能建工程（P-14）。
- 按工程的角色（R140、R142 到 R144 的 `roles`）：生产面的事，不上开发面（任务书 §11 第 8 条）。
- 用户组可见的服务器（R074 的 `servers`）：第 6 片。
- 人员组、分栏、归属工程、单点登录身份名、员工编号（R075 到 R077、R136 的一部分）：这家单位的人员模型。
- 自己改自己的显示名：没有提出这个需求。
- 找回口令：要邮件或短信通道。
- 改用户名：同身份规格。
- 改号时改用户组：用户组有自己的一组路由。
- 用户组和工程数量的上限：没有提出这个需求。
- 整体替换的版本号（两个管理员同时改同一个组，后发的盖掉先发的）：这是整体替换的本义，七个人的单位里极少发生。真遇到了再给请求带版本号、落后了回 409。
- 转手工程（换创建者）：没有提出这个需求。所以建过工程的账号只能停用，不能删（G-24）。

## 未确定

- 并发下的护栏（G-20）只在真 Postgres 上验：进程内的库一次只跑一个事务，造不出两个管理员同时互相降级。
- 真实域名下的端到端（任务书 §11 条款 4）：本机只能走回环加页面代理，留到发布前。
