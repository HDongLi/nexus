## 它管什么

管四条路由（清单、新建、详情、改显示名和头像字）和它们底下的东西：工程记录、平台替人建并管理的裸仓库、初始提交里的三个文件、谁看得见哪个工程、两个事件、一个配置项。

不管：服务器端的工作树和 AI 会话怎么用仓库（第 4 片）；用户组和授权的界面与路由（第 3 片，这一片只给「谁能看见」留一个可替换的判断点）；预览、端口、发布（第 6 片及以后）。旧系统的哪些做法属于这家单位而不是通用机制，见「明确不做的」。

## 要求

每条三样：一句要求、来源、怎么验。验收只用四种测试：单元测试不碰数据库；集成测试用进程内数据库打真路由，凡要读库的断言都放这里；契约测试读生成的接口文档；端到端起真浏览器。涉及仓库的验收把 `PROJECTS_ROOT` 指到临时目录，用真的 `git`；要造失败、超时或数调用次数时，把模块注入的 git 执行器换成桩。

### 路由与总则

| 路由 | 访问级别 | 请求体 | 成功时 |
|---|---|---|---|
| `GET /api/v1/projects` | user | 无 | 200 `{ "projects": Project[] }`，新的在前 |
| `POST /api/v1/projects` | user | `{ "slug": 短名, "displayName"?: 显示名, "avatar"?: 头像字 }` | 201 `{ "project": Project }`，仓库已可用 |
| `GET /api/v1/projects/{projectId}` | user | 无 | 200 `{ "project": ProjectDetail }` |
| `PATCH /api/v1/projects/{projectId}` | user | `{ "displayName"?: 显示名, "avatar"?: 头像字 }`，至少带一个 | 200 `{ "project": Project }` |

`Project` 一律是 `{ "id", "slug", "displayName", "avatar", "createdById", "createdAt", "updatedAt" }` 七个键，都是字符串；时间是带时区的 ISO 8601。`createdById` 是创建者的账号编号。`ProjectDetail` 是 `Project` 加一个 `head`：`{ "commitId", "committedAt", "subject" }`，默认分支最新一次提交的编号、提交时间、标题。

| 错误码 | 状态码 | 什么时候 |
|---|---|---|
| `projects_slug_taken` | 409 | 新建时短名已被占用 |
| `projects_forbidden` | 403 | 改一个看得见、但不是自己建的工程，又不是管理员 |
| `projects_creation_failed` | 500 | 仓库没建起来 |

找不到和看不见一律是已有的 `not_found`（404）；形状不合是已有的 `invalid_request`（400）；详情读不到提交是已有的 `internal_error`（500）。`message` 是给人看的，文案不固定。

### 事件

| 事件 | 什么时候发 | `subject` | payload 的键 |
|---|---|---|---|
| `projects.project.created` | 工程建成 | 工程编号 | `projectId`、`slug`、`actorId` |
| `projects.project.updated` | 显示名或头像字变了 | 工程编号 | `projectId`、`slug`、`actorId`、`changes` |

`actorId` 是调用者的账号编号。事件的主体是工程，不带操作者，事后就查不出是谁改的，所以每个由人触发的写事件都带上它（编排者 2026-11-27 采纳）。`changes` 只列真变了的键，每个键带 `from` 和 `to`。

| P-34 事件信封 | 系统应按上表发两个事件：`source` 是 `projects`，`traceId` 是该请求的请求号。 | 编排者的约定；`actorId` 是本规格加的，身份规格把账号编号定为「记录这件事是谁做的」用的 | 集成测试——逐场景断言事件的类型、`source`、`subject`，payload 的键集合与表一致 |

## 旧系统的做法与教训

读的是旧仓 `server/nexus_server/` 下的 `dev/routers/projects.py`、`dev/deps.py`、`dev/ports.py`、`core/auth.py`，页面 `server/web/dev.html`、`devpage.html` 的调用处，本机端 `client/nexus_client/` 的转发处，加 `server/tests/test_avatar_field.py`、`test_ports_scaffold.py`。行号是 2026-11-27 的现状。旧系统一次都没跑过，标「读码所见」的都没有实测。

- **清单是扫目录扫出来的。** 没有工程记录：根目录下带 `.git` 的文件夹就是一个工程，按目录名升序（projects.py:104-106）。每个工程同步跑 3 到 4 次 git：生产裸仓的 `main`、工作树的 HEAD、当前分支、脏树（projects.py:68-69、88-90）；读一次工程配置文件，最多再读 7 个源码文件找版本号（projects.py:48-62、75）；显示名和头像字把整份平台配置重读三遍（projects.py:24-42、85-86、107）。页面每 5 秒重取一次（tick_routes.py:1-5、27）。单次 git 的超时是 30 秒（deps.py:70-76）。（→ P-07、P-09）

旧清单项的每个字段去了哪里（字段表在 projects.py:83-95）：

| 旧字段 | 旧系统怎么得到 | 新版 |
|---|---|---|
| `name` | 目录名 | `slug` |
| `alias`、`avatar` | 重读平台配置 | `displayName`、`avatar`，记录上的字段 |
| `head` | 生产裸仓的 `git rev-parse main`（projects.py:67-69） | 挪到详情的 `head.commitId`，补上提交时间和标题（P-25） |
| `dev_head`、`branch`、`dirty` | 工作树上三次 git：HEAD、当前分支、`status --porcelain`（projects.py:88-90） | 这一片没有工作树，不回报 |
| `app_version` | 正则扫源码文件（projects.py:48-62） | 不做，见「明确不做的」 |
| `form`、`form_note`、`url_override` | 读工程的配置文件（projects.py:73-82） | 这家单位的应用形态，不做 |
| `projects_root` | 配置常量（projects.py:113） | 不出接口（P-05） |
| `alias_map` | 全量显示名表（projects.py:107-109） | 不做，清单里每条自带显示名 |
- **清单外露了两样东西。** 响应带工程根目录的绝对路径（projects.py:113）。显示名表是全量的：先建表、后过滤，看不到的工程的显示名也一起回给页面（projects.py:107-111；dev.html:1739 的注释）。（→ P-05、P-08）
- **谁能看。** 管理员全量；其余人是他所属各用户组 `owned` 的并集，每次请求读盘现算（auth.py:160-172；projects.py:118）。来自本机回环的请求一律当管理员（auth.py:176-178）。看不见的工程回 403，文案说明它不在你的归属里（deps.py:27-37）。页面在服务端的过滤之外还按加载时的快照滤了一遍，新建的工程因此在侧栏隐身过（dev.html:1749-1757 的注释；旧仓 `docs/版本历史/server.md` 的 0.58.01 条）。（→ P-08、P-10、P-11）
- **谁能建，短名怎么查。** 只有管理员能建（projects.py:164-165；auth.py:202-207）。短名先转小写再查：2 到 40 个字符，字母开头，不合回 400（projects.py:171-173）；重名回 409（projects.py:176-177）。成功响应带两个目录的绝对路径和端口号（projects.py:267-268）。（→ P-05、P-13 到 P-15）
- **新建做了什么。** 裸仓、工作树、三个骨架文件、挑端口、首提交并推送、两个钩子、一条脚手架任务（projects.py:183-240），之后再改用户组的 `owned`（projects.py:245-256）和显示名表（projects.py:260-266）。三个骨架文件：`README.md` 是标题加一句说明（projects.py:188-190）；`nexus.json` 是端口、健康路径、启动命令、构建命令、助手类型、部署服务名（projects.py:194-209）；`AGENTS.md` 是接入约定、回执格式、平台契约区（projects.py:135-156）。都是这家单位的样子。提交后自动推送的钩子把推送失败写进一个日志文件，工作树和裸仓可能悄悄分叉（projects.py:157-161）。（→ P-17）
- **挂组那段从未生效。** projects.py:249 引用的 `ident_user` 全文件没有定义，抛出的异常被第 255 到 256 行吞掉，这半段一次也没跑过；组员要等管理员在授权面手动挂上才看得到（projects.py:241-244 的注释；B-001）。（→ P-10、P-12）
- **新建失败留下什么。** 回滚只删裸仓和工作树两个目录（projects.py:228-231）。挑走的端口已经写进配置，不跟着回滚（projects.py:193；ports.py:76-83）；脚手架任务和后面的步骤在回滚之外，那里出错时仓库和工作树已经落地（projects.py:233-266，读码所见）。报错文案带原始异常（projects.py:231）。建仓路径上的 git 调用没有超时（projects.py:179-180、184-187），页面给它等 5 分钟（dev.html:1976）。本机端的注释记着「建仓成功、克隆失败」留下的半截孤儿（client/nexus_client/main.py:293-296，读码所见）。（→ P-05、P-20、P-22）
- **连续三个版本建工程必 500。** 0.58.02 起新建读了没声明的请求字段，0.58.05 才补上（旧仓 `docs/BUGS.md` 的 BUG-2026-11-17-170 条；projects.py:125-128 的注释）。而且仓内三个调用处没有一个把显示名送到服务端：本机端转发时只带短名和形态，显示名只存在本机（client/nexus_client/server_api.py:443-445；main.py:284、323）；直连的页面不带（dev.html:1976）；带显示名的那张页面要经本机端转发（devpage.html:2160）。读码所见。（→ P-07）
- **显示名与头像字。** 存在平台配置文件的两张表里，空值即删键（projects.py:289-295、311-317）。超长不报错，直接截断（projects.py:287、309）。除了看不看得见没有别的检查：凡是看得见的人都能改（projects.py:21；deps.py:27-37）。设置对话框把服务器上两棵目录的绝对路径写死给人看（dev.html:2927）。（→ P-27 到 P-30）
- **AI 会话配置，只记事实。** 三个字段：`assistant`（用哪个助手，缺省 `claude`）、`cwd`（工作目录）、`args`（启动参数），存在工程工作树的 `nexus.json` 的 `ai` 节里（deps.py:140-148；projects.py:347-348）。写接口值相同就不写（projects.py:338、349-350）；不同就改文件，以服务端的身份 `git add`、`git commit`，各 15 秒超时（projects.py:353-357），失败回 500 并带标准错误输出的末尾（projects.py:359）。读写都没有测试。（→ 第 4 片）
- **R099。** 单工程接口回的就是清单项（projects.py:272-274），唯一调用方是本机端的版本核对（R099 的清点结论）。（→ P-25）

## 明确不做的

- 裸仓加工作树加双向钩子、Windows 形态的启动命令、脚手架首单、端口登记：R098 里这家单位的做法，归定制规格。这一片只建裸仓。
- 显示名和头像字存进平台配置、随发布下发生产面：R100、R101 的做法。新版里它们只是记录上的字段。
- R099 单工程版本接口：已判退役。它真正有用的信息是「默认分支现在停在哪个提交」，由详情的 `head` 承接（P-25）；其余字段的去向见上面那张表。
- AI 会话配置的读和写：R102、R103，第 4 片。
- 从源码文件里扫应用版本号（projects.py:48-62）：这家单位工程家族的约定。工程要让平台知道自己的版本，走健康检查自报（清点表 C001 行的结论：由 R057、R160 承接）。
- 开发头、当前分支、脏树：这一片没有工作树，无从回报；第 4 片建了工作树再定。
- 删除和归档、分页、搜索、改短名、上传图标、把工程迁到别的仓库地址。
- 建工程的配额：没有提出这个需求。
- 清单的拖拽排序：旧页面把顺序存在浏览器本地（dev.html:1746-1757）；新版的次序由接口定（P-08）。

## 未确定

- 仓库从外面怎么克隆：走 SSH 还是 HTTP，地址长什么样，这一片没有定。P-16 验收里的克隆是从 `PROJECTS_ROOT` 本地克隆。
- 新建接口的耗时预算：任务书 §10.3 写接口 p95 不超过 200 毫秒；新建要跑几条 git 命令，要多少没有量过。
- 进程在建仓途中崩溃会留下一个没有记录的仓库目录。目录名取编号，它不占短名（P-19）；要不要在启动时清扫，没有定。
- 创建人的账号以后被删除时工程怎么办：已定（2026-11-27）——建过工程的账号不许删。靠工程表上的引用约束保证：创建者编号引用账号表，`ON DELETE RESTRICT`，随这一片的表一起建；删号时库拒绝，见[人员规格](people.md) G-21。
- 第 3 片之后「谁能改」要不要放宽到用户组的成员：已定（2026-11-27）——不放宽，见[人员规格](people.md) G-35。第 3 片给这个模块加一张关系表（哪个组看得见哪些工程）和两条路由，见人员规格 G-31。
- git 命令的缺省超时 30 秒是初值，沿用了旧系统单次 git 的超时（deps.py:73），没有实测依据。
- 旧系统的工作树和裸仓在两棵目录树下（projects.py:134、174-175）；旧仓库怎么搬进新版的根目录，是客户线迁移的事。
