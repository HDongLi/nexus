## 三处要订正任务书的地方

**1. 没有单独的 `tsgo`。** 任务书的质量闸一栏写的是「tsgo 类型检查」。复核：`typescript@7.0.2` 这个包只有一个可执行文件 `tsc`，它本身就是原生编译器。`@typescript/native-preview` 是正式发布之前的预览线，不再需要。所以质量闸里写 `tsc` 即可。

**2. TypeScript 7 不再带老的编译器接口，部分工具要配 TypeScript 5。** 实装验证：

- `typescript@7.0.2` 的包里，`import ts from "typescript"` 只剩 4 个导出，没有 `ts.factory`、`ts.createPrinter`。老的 JavaScript 编译器接口换到了 `typescript/unstable/*` 一组新入口。
- `openapi-typescript@7.13.0` 在运行时要 `ts.factory`，它自己声明的兼容范围是 `typescript ^5`。放在 7.0.2 旁边直接崩：`dist/lib/ts.mjs:11` 报 `Cannot read properties of undefined (reading 'createKeywordTypeNode')`。换成 `typescript@6.0.3`，同一份 OpenAPI 文档 54 毫秒生成成功。骨架落地时装的是 `typescript@5.9.3`：生成器自己声明的范围是 5，6 能跑但不在它声明的范围里。

靠老接口吃饭的工具不止这一个的可能很大。骨架落地时逐个实装验证，结果见文末「骨架实装结果」。（2026-11-26 订正：这一条和决定 2 原先写的是 6。）

**3. Node 26 已经是 LTS。** 任务书推荐 26 LTS。开发机现在装的是 24.22.3，两条线都在支持期内。

## 决定

1. **上表就是锁定的基线。** `package.json` 里按上表写版本范围；升级走新的决策记录或变更提案，不随手升。
2. **仓里有两套 TypeScript，各管一件事。** 全仓用 `typescript@^7` 做类型检查；只有「契约生成」那一个包（`packages/api-client`）另外声明 `typescript@^5.9.3`，给 `openapi-typescript` 用。除它之外任何包都不许声明 TypeScript 5，`tools/gates/ts-versions.ts` 在 L0 闸里检查。契约包自己的类型检查也用根上的 7。（2026-11-26 订正：原先写的是 `^6`。）
3. **Node 的支持下限是 24.12，CI 在 24 和 26 两条 LTS 线上各跑一遍。** 开发机暂留 24 线：换一条线是五分钟的事，而这台机器上还跑着别的工具，没有人在场时不动它。
4. **`oxfmt` 钉精确版本**，不带范围。它在 1.0 之前，小版本之间格式化结果可能变，一变就是全仓的格式差异。
5. **后端的 OpenAPI 中间件沿用 `@hono/zod-openapi`。** 另有 `hono-openapi 1.6.0`，好处是不绑定校验库，但它自述「仍在开发中」。列入观察，骨架落地后看它稳定了再议。

## 没查到的

- **`msw 3`、`shadcn` 的命令行在 TypeScript 7 旁边能不能跑**，还没有实装。骨架用不上它们：没有需要拦截的请求，界面件是手写的。`shadcn` 的配置文件 `components.json` 写了，命令行没跑过。
- **PGlite 顶替真 Postgres 的边界**，现在只知道迁移能在它上面从头重放、重放幂等。真库上的复跑写在 CI 里（每次推送带一个 Postgres 服务），但工作流本身还没有被观察过。

TypeScript 7 旁边的结论：**凡是自己去找 `typescript` 的工具，都要逐个实装验证，不能看它声明的兼容范围。** 这一天栽了两次，`openapi-typescript` 一次，`dependency-cruiser` 一次；后一次更隐蔽，因为它不崩，只是悄悄什么都没看。

## 后果

- 实现代理装依赖时以本表为准，不用自己去找最新版。
- 「两套 TypeScript」是一处不优雅，但它是当前工具生态的现实：类型检查这一步已经换到原生编译器，代码生成那一步还没有。等 `openapi-typescript` 支持新接口，这条决定就可以撤掉。
- 冒烟没做之前，不给任何客户承诺「麒麟上能跑」。
