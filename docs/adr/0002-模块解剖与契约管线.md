## 背景

骨架要定两件事：所有模块长成什么形状，前后端之间那唯一的一条接缝怎么走。形状定错了，后面每个模块都要迁一次。样板是两个最小的模块：`modules/event-log` 和 `modules/system`。

## 决定

1. **一个模块是一个目录、一个出口。** `modules/<名字>/` 里有 `index.ts`、`routes.ts`、`service.ts`、`repo.ts`、`schema.ts`、`events.ts`、`module.md` 和同目录的测试。别的模块和应用只能 import `index.ts`。伸进内部文件由依赖方向检查报错，只做类型引用的伸手同样算。规则是按 `modules/` 目录现读现生成的，新建一个模块就自动多一条。
2. **路由分两步：先声明，再绑定。** `route(访问级别, 形状)` 只产出数据，`bind(声明, 处理函数)` 才接上行为。生成契约文档时只读声明，所以不用数据库、不用起进程。处理函数只做三件事：解析入参、调用用例、把结果交回去。
3. **访问级别没有默认值。** `public`、`user`、`admin` 三选一，每条都要写。访问闸按「方法加路径」查表，查不到的一律回 404：忘写访问级别的路由不存在，而不是默认公开。
4. **前后端只通过生成的契约包说话。** 后端的全部路由声明合成一份 OpenAPI 3.1 文档，文档生成 `packages/api-client` 的类型和一个类型安全的客户端。两样产物都入库。页面不手写接口路径和返回类型，也永远不 import 服务端的模块。`apps/web` 的 tsconfig 里没有服务端代码可 import，依赖方向检查也会拦。
5. **失败有统一的形状。** `{ error: { code, message, requestId } }`。`code` 是给程序认的稳定标识，`message` 是给人看的一句话，`requestId` 对日志。每个请求带请求号，写进日志也写进响应头。页面上的错误用卡内或行内常显提示，不用浏览器原生弹窗。
6. **事件是模块之间唯一的「事后」通道，并且可以是事务性的。** `EventLog.emit(事件, 事务?)` 把事件写进一张表，和业务写入同一个事务提交。别的模块订阅事件来反应，不互相拉进对方的事务，也不在别人的表上写数据。
7. **数据库两个驱动，一套类型。** 没给 `DATABASE_URL` 时用进程内的 Postgres（PGlite），开发者不用先装数据库，测试每次从空库开始；给了就连真库。模块只认 `Db`、`Tx` 两个类型，不知道背后是哪一个。迁移是线性的 SQL 文件，只前进。
8. **应用层只做装配。** `apps/api` 里是组合根、中间件和进程生命周期，没有业务。模块需要的东西（仓储、事件、时钟）都由应用显式传进去，所以测试不用起进程就能测模块。
9. **骨架期的鉴权明说「没接」。** 需要登录的接口回 501 `auth_not_wired`，页面上写「身份模块还没有接入」。这是「没有声明就不放行」的另一半：明知道还没做，就不假装做了。身份模块接入后，组合根换成真正的验证器。

## 验证

- 依赖方向检查对四种违规各报对应的规则（见落地文档的表）。
- 端到端抓到决定 5 的一处漏洞：客户端库读过响应体之后，翻译函数再去读就读不到了，失败原因丢在半路。修法是让翻译函数收客户端返回的整个结果。单元测试原先只拿一个新鲜的响应对象测，所以没发现；现在改成走真实客户端。

## 后果

- 新模块照样板长，`pnpm new:module` 生成的就是这套形状。
- 一条路由要被端到端地接受，要过四道：声明里有访问级别、契约产物重新生成、类型贯通到页面、端到端走一遍。
- 决定 9 意味着现在所有要登录的接口都不可用。这是有意的：第一条真正的业务路由必须和身份一起进来。
- 契约生成那一步依赖私有的 TypeScript 5（[0001](0001-技术栈版本复核.md) 决定 2）。文档里共享的错误形状是内联的而不是引用，原因记在 `packages/http-kit/src/responses.ts`。
