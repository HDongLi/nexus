| 项 | 内容 |
|---|---|
| 日期 | 2026-11-26 |

| 状态 | 进行中，第 1 片在做。每片的进度见文末「切片顺序」 |
| 决定 | [0004 视觉语言](../../adr/0004-视觉语言.md)；每一片的契约、表、事件在同目录的 `design-<序号>-<名字>.md` |

## 为什么

旧系统里开发者每天用得最多的是开发面：一张管理控制台（人、组、工程、服务器）和一张工作台（我的工程、预览、发布、AI 会话）。新版的底座已经有了（可运行骨架、视觉语言），接下来把它一页一页做出来。

开发面有 144 条路由，其中 80 条进内核（`docs/parity/routes.csv` 里 `services` 含 `dev` 的行）。一次做完不现实，先画一堆没有接口撑着的页面也不行：界面上每个动作背后都得是一次 API 调用（主张 P1）。所以按**垂直切片**推进，每一片自带后端模块、生成的契约和页面，做完一片就能用一片。

还有两件事要等裁决清单答复，不在上面的表里：DSH 入口三件（R046–R048，默认进定制包）；预览要不要以服务端形态重建（裁决清单 `preview-relay` 一题，默认重建，重建的话排在第 6 片之后单独成片）。

## 每一片怎么落地

规格 → 设计 → 实现 → 独立审查 → 合并。

- **规格**由读旧代码的代理写，落在 `docs/spec/<领域>.md`，用「当…时，系统应…」的句子，每条带来源。旧仓只读。
- **设计**写契约、表、事件，落在 `design-<序号>-<名字>.md`。契约写定的那一刻，前端和后端可以并行。
- **实现**分后端、前端两张卡，范围不相交。
- **审查**由干净上下文的代理做：只看任务卡、规格、改动和闸的输出。修复者不自验。

## 不做什么

- 不做生产面、控制芯核的页面，它们各有自己的提案。
- 不内嵌 DSH 或任何第三方会话界面。
- 不复刻旧页面的结构。旧的两张页面各是三四千行的单文件；新版一页一个路由，组件住在 `packages/ui-kit`。
- 不做本机端做过的事。本机端不进新版（任务书 §2.2）。
