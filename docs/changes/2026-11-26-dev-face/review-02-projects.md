## 做得好的地方

- **可替换件的设计让审查也能「换桩」**：git 执行器、可见性判定、仓储、时钟全部从构造参数进来，集成测试和真启动走同一份 `composeApp`——本次 M1–M6 每一条改坏都能精确打在单一职责上，实弹检查也能在真进程上复现集成测试同款场景。
- **失败路径是一等公民**：四步 git 失败逐一遍历、挂起桩验「子进程真死了」（`eventuallyDead`）、仓储抛错后「目录/记录/事件」三项快照前后相等——旧系统「建仓成功、克隆失败留孤儿」的那一类坑被系统性钉死。
- **P-11 的测试写法经得起破坏**：比对「看不见 vs 不存在」彼此而非比对固定文案，我第一次对称性改坏没骗过它，第二次让它走了不同分支才红——这正是这条规格的精髓。
