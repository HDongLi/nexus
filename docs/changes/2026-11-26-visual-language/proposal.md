| 项 | 内容 |
|---|---|
| 日期 | 2026-11-26 |
| 对应 | 产品负责人当天的要求：看几家做得好看的同类产品是怎么做的，把做法用到这里 |
| 状态 | 已落地，见 [design.md](design.md) |
| 决定 | [0004 视觉语言](../../adr/0004-视觉语言.md) |

## 为什么

产品负责人自己做过界面，经验是：界面很难做，要靠一页一页反馈细节才能磨到一致，而使用体验直接决定用户对产品的感受。骨架页当时的样子是组件库的默认值拼出来的，离想要的水准差得远。

后面的页面是由很多互不通气的代理并行做的。一致性不能指望逐页审出来，要在底座上决定一次：可选的值只有一小把，并且每个都有名字。

## 改什么

- 一套视觉规则，每条取值写明是从哪家产品量来的（决策记录 0004）。
- `packages/ui-kit/src/styles.css`：字体、字阶、墨色、强调色、边框、层次、圆角、版心，深浅两套。全仓只有这一个文件写数值。
- 通用组合件：应用框架（侧栏、页头、内容区）、面板、按钮、状态标记、说明列表、行内代码、输入框、提示卡。
- 骨架页按这套重搭，顺带修掉时间显示和窄屏布局两个问题。

## 不做什么

- 不做任何业务页面。对话流、表格、表单各自的专项规则，等真正做到那一页时再定。
- 不加载网络字体，不引入现成的组件主题。
- 不搬任何一家的品牌元素：标志、字体、配色的原值都没有照抄。
