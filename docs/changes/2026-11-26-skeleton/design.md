# 设计：可运行骨架

跟着 [proposal.md](proposal.md)。这里记落地时的形状、验过什么、没做什么。

## 形状

```
apps/api ──装配──▶ modules/system ──▶ modules/event-log ──▶ packages/{contracts,db,http-kit}
apps/web ──只认──▶ packages/api-client（由契约生成）、packages/ui-kit
```

### 契约

| 方法与路径 | 访问级别 | 作用 |
|---|---|---|
| `GET /api/v1/system/health` | public | 健康探测。数据库连不上回 503，响应体形状不变 |
| `GET /api/v1/system/info` | user | 版本、本次启动、最近五次启动 |
| `GET /api/v1/doc` | admin | OpenAPI 文档 |

产物是 `packages/api-client/openapi.json` 和 `src/schema.d.ts`，入库。改了路由声明要跑 `pnpm contracts`，L2 会比对。

### 表

事件记录模块拥有一张表 `events`：编号、类型、来源、主体、payload、发生时间、链路号。迁移在 `apps/api/drizzle/`，线性，只前进。

### 事件

`system.started`，payload 是 `{ bootId, version, node }`。发事件走 `EventLog.emit`，可以和业务写入放在同一个事务里。

### 页面

一页。调上面两个接口，成功的显示，失败的用卡内常显提示把原因和请求号摆出来。

## 今天验过什么

全部在开发机上做，数字是无缓存时的值。耗时随机器负载变：内存吃紧、杀毒软件在扫刚写入的文件时，同一套闸慢到过 10 倍（L0 到过 20 秒）。

| 验的是什么 | 结果 |
|---|---|
| L0 格式、lint、依赖方向、编译器版本、请求路径零同步、任务范围 | 2 秒，全绿 |
| L1 类型检查、单元测试 | 7.6 秒，全绿。单元测试 30 条 |
| L2 集成测试、契约一致性、迁移可重放 | 10 到 18 秒，全绿。集成测试 6 条，跑在进程内库上，带真迁移 |
| L3 端到端 | 14.5 秒，3 条用例在真浏览器里通过，跑完不留进程 |
| `pnpm dev` | 两个服务起来并打印真实端口；只杀后端，启动器带着页面服务一起退出 |
| 依赖方向闸会不会红 | 四种违规各放一个进去，各自报对应的规则：页面直连模块、模块之间只做类型引用的伸手、基础包反向依赖模块、路由文件直接碰仓储 |
| 同步调用闸会不会红 | 模块辅助文件、后端应用层里各放一处，各自红；启动文件里的放行 |
| 模块脚手架 | 生成一个模块，它自己过了类型检查和 2 条测试；依赖方向闸自动给它加上「内部文件只许走出口」的规则 |

过程中抓到并修掉的问题，按发现顺序：

1. **依赖方向检查是假绿。** 检查器拿不到能用的 TypeScript 编译器（7.0 的接口它用不了），于是一个 `.ts` 文件都没读，打印一条警告，退出码还是 0。换成它能用的解析器，并加一道核对：每个源文件都必须在它的巡查范围里。
2. **同一个检查器不读包的 `exports`。** 出口写在 `./src/index.ts` 的基础包全被当成「解析不到」。让它按 Node 的方式解析。
3. **翻译接口失败时丢了原因。** 客户端库已经把响应体读过，翻译函数又去读一遍，读到空的。页面上「身份模块还没有接入」显示成了「服务器出了问题」。端到端抓到的；改成把客户端的整个结果交给翻译函数，单元测试改成走真实客户端。
4. **端到端的端口对不上。** Playwright 在每个工作进程里都重新加载配置文件，端口被各算各的。把定端口挪到 `apps/web/e2e/run.ts`，用环境变量带进去。`pnpm dev` 里同源的一个隐患一并修掉。
5. **任务名没登记。** `migrate:check` 没写进 `turbo.json`，编排器直接报错。
6. **Vite 的入口路径取不到。** 新版 Vite 的包不对外暴露 `bin/`，改成从它的清单里读。

## 没做、留给后面的

- **真 Postgres 上复跑。** 迁移自检支持 `DATABASE_URL`，CI 里每次推送带一个 Postgres 服务；开发机上没装 Postgres，这一条本机没跑过，CI 的结果我也看不到（本机没有 `gh`）。
- **CI 工作流本身没被观察过。** 写好了、推送后会在 GitHub 上跑，第一次跑的结果要人看一眼。
- **身份。** 需要登录的接口回 501 `auth_not_wired`。这是明说「还没接」，不是假装鉴权在工作。
- **真实入口形状的端到端。** 现在走的是本机回环加页面代理。真实域名、Origin、真 Cookie 等身份模块和域名接入。
- **性能预算进 CI。** 闸里只报不拦；`GATE_BUDGETS=strict` 时才拦。
- **合并队列。** 任务书 §6.6 写了，仓库现在还是单人直推 `main`。等并行开发开始前再定（GitHub 的合并队列对私有仓另有计费）。
- **任务范围闸只在任务分支上生效。** 这一版骨架是直接在 `main` 上由编排会话建起来的，任务卡是事后补记的，格式照任务书 §6.4。范围闸在一条临时任务分支上验过（越界红、界内绿）。
